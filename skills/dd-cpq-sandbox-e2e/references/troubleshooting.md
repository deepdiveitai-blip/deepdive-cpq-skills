# Troubleshooting — errors, wrong numbers, "it does nothing"

> Installed build 0.1.0-9 (commit 31444bb) · Verified 2026-10-07 in cpq-pkg.
> The one place Claude goes first for an error message, a wrong number, or
> "nothing happened." Read this before opening a feature module — it routes
> you to the right one.

## 1. How to diagnose

Work top to bottom; stop at the first step that resolves it.

1. **Get the exact text.** Ask for the message verbatim, or the `DD-XXXXXX`
   reference / trace id shown. Don't paraphrase — "refused" and "blocked"
   point at different rows below.
2. **Find the row.** Section 2 (error messages) if something refused;
   section 3 (wrong number) if a price/discount/MRR looks off; section 4
   ("it does nothing") if a button, tab or field is missing; section 5 if
   install/access is the problem; section 6 for a known product gap.
3. **Run the row's check query.** Each row below names the object/field to
   query with `sf data query`, prefixed `DDCPQ__` on every custom
   object/field (never on standard objects).
4. **Read the price waterfall or run a read-only preview.** For anything
   price-shaped, open the line's waterfall in the cart (click the price →
   "Explain price"), or run the read-only preview — **never call
   `dd/v1/commit`**:

   ```bash
   sf api request rest "services/apexrest/DDCPQ/dd/v1/price?includeWaterfall=true" -o <alias> --method POST --body @body.json
   ```

   ```json
   {
     "quoteId": "<0Q0…>",
     "selections": [{ "localKey": "x", "productId": "<01t…>", "quantity": 1 }]
   }
   ```

   Read `lines[].waterfall[]` stage by stage; each stage names the rule that
   fired (`sourceRuleId`) or why it passed through. This is read-only — it
   writes nothing, so it is always safe to run, including while diagnosing.

5. **Engine Health run / error log, by reference code or trace id.**

   ```bash
   # a quote's last kept run
   echo '{"action":"telemetry.last","payload":{"quoteId":"<0Q0...>"}}' > body.json
   sf api request rest "services/apexrest/DDCPQ/dd/v1/admin" -o <alias> --method POST --body @body.json

   # admin-only: every kept error, or one by its DD-XXXXXX reference
   echo '{"action":"errors.list"}' > body.json
   sf api request rest "services/apexrest/DDCPQ/dd/v1/admin" -o <alias> --method POST --body @body.json
   ```

   An empty result usually means `Engine_Telemetry_Persist` / `Error_Log_Enabled`
   are off (both default **off**) — turn them on in **DD CPQ Settings →
   Engine Health**, then reproduce; nothing is retroactive. `errors.list`
   needs `Administer Pricing`; a quoting-only user gets a 403.

6. **Open the feature module** named in the row's last column for the full
   story, the exact build-it steps, and more Q&A.

## 3. Wrong number index

| Symptom                                                                             | Likely cause                                                                                                                                                           | Module                                                                                                                                     |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Price ignores a rule you just wrote                                                 | Rule set still Draft (Rules Studio always saves new sets Draft)                                                                                                        | [golden-path.md](golden-path.md), [concepts.md](concepts.md)                                                                               |
| Price ignores an Active rule                                                        | Target doesn't cover this product; for `PricingRule__c`/`EligibilityRule__c` a blank target means **nothing**, not every product (help text says otherwise: DDCPQ-121) | [price-rules-and-contract-prices.md](modules/price-rules-and-contract-prices.md), [eligibility.md](modules/eligibility.md)                 |

| `PctOfList` gives less discount than expected                                       | A `ContractPriceRule__c` already lowered the seed — the percent bases off the contract price, not list                                                                 | [price-rules-and-contract-prices.md](modules/price-rules-and-contract-prices.md)                                                           |

## 5. Install and access problems

From [golden-path.md](golden-path.md), expanded with every failure mode a tester can hit before the first quote prices.

| Symptom                                                                         | Cause                                                                                              | Fix                                                                           |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `sf data query` on `Organization` shows a real production org                   | Stop immediately — never install here                                                              | Use a Developer Edition or sandbox only                                       |
| `NamespacePrefix = DDCPQ` already on the org                                    | That is a DEV team org, not a clean one                                                            | Use your own Developer Edition/sandbox                                        |

| Install fails naming `Quote` or `QuoteLineItem`                                 | Same as above — Quotes weren't enabled first                                                       | Enable Quotes, then reinstall                                                 |
| Install fails naming `Order` or `OrderItem`                                     | Order Settings not enabled                                                                         | Setup → Order Settings → Enable Orders → reinstall                            |
| `sf package installed list` doesn't show DD CPQ Engine 0.1.0.9                  | Install still in progress (can take 5–10 min) or failed silently                                   | Re-run the list command; if it never appears, read the install error verbatim |
| "Working on a quote needs the "Build Quotes" permission" for a System Admin     | DD CPQ checks its own custom permission in Apex — Modify All does not satisfy it                   | `sf org assign permset -n DDCPQ__DD_CPQ_Engine_Admin`                         |
| No Configure Products action on the Quote layout                                | Package ships the Quick Action but cannot place it on a layout it doesn't own                      | Drag it onto the Quote Layout's Mobile & Lightning Actions section by hand    |
| Opportunity has no "Renewal" Type value                                         | Fresh orgs have no such picklist value, and the golden quote needs it                              | Setup → Object Manager → Opportunity → Type → add value `Renewal`             |
| A beta-package upgrade is needed                                                | 0.1.0-9 cannot be upgraded in place — upgrading means uninstall, which deletes every DD CPQ record | Never uninstall on your own; ask Venkat which build to use                    |
| `sf` says the org is expired or auth failed                                     | Session timed out                                                                                  | `sf org login web` again with the same alias                                  |
| Settings tab shows defaults even after you think you saved                      | Either the save didn't actually happen, or you lack `Administer Pricing`                           | Confirm the save succeeded; assign the Admin permission set                   |
